# 安全策略

TidyMate 的定位是"可以放心指向真实照片和文档目录的工具"。因此安全问题在这里不是加分项，
是准入项。

## 报告漏洞

**不要开公开 issue。**

- 首选：GitHub 私有安全公告（仓库 Security 标签页 → Report a vulnerability）。
- 若暂时无法使用，请通过仓库维护者的公开联系方式提出，并只说明"需要私下渠道"，
  不要在正文里贴利用细节。
- 我们会在 **72 小时内**确认收到，并在 **14 天内**给出初步判断（确认/不确认/需要更多信息）。

请包含：受影响版本、复现步骤、最小化的目录结构与规则文件、以及你观察到的实际行为。
**不要**附带真实个人文件的路径或内容；用 `C:\Users\<user>\...` 占位即可。

## 什么算安全问题（在本项目里）

按铁律，以下都当安全漏洞处理，而不是普通 bug：

1. 任何形式的**永久删除**（含误走 `shutil.rmtree`、绕过 send2trash、清理临时目录时删到用户文件）。
2. **覆盖已存在的文件**而没有经过 skip/rename/ask 策略与显式确认。
3. **规划与执行不一致**：dry-run 报告与 `--apply` 的实际结果对不上。
4. **状态造假**：failed/skipped 被计入 success，或统计数字无法由日志复现。
5. **路径逃逸**：目标路径等于源路径的祖先（含自身）、或落在源子树内、或经 `..`/junction 绕出预期目录。
6. **黑名单绕过**：配置、环境变量、命令行参数、长短路径写法能绕开系统/程序目录拒绝。
7. **撤销日志不可信**：日志可被普通用户伪造、或被篡改后仍能回滚成"成功"。
8. **未声明的网络行为**：任何未经用户显式开启的联网、遥测、崩溃上报、更新检查。
9. **AI 功能越界**：读取文件内容、上传内容、或在未确认的情况下自动执行建议。

## 威胁模型（当前阶段的明确立场）

| 威胁 | 我们的态度 |
| --- | --- |
| 用户误操作（把整个 D 盘指给工具） | 黑名单 + 祖先检测 + dry-run 默认，第一优先级防 |
| 规则写错导致文件被搬进奇怪的地方 | 模板白名单严格拒绝，不猜；预览必须逐条可读 |
| 断电/崩溃导致半完成状态 | 先写日志再动文件；状态不明的条目绝不回滚成成功 |
| 恶意构造的路径（`..`、`\\?\`、UNC、junction） | 执行前逐条规范化并重新校验，不信任规划期结果 |
| 供应链 | 运行时依赖极少（当前仅 `typer`）；CI 不使用来源不明的 action |
| 本地攻击者篡改日志 | **当前不防御**（见"已知非目标"） |

## 已知非目标（现阶段）

- **不是加密工具**：日志与配置是明文。同一台机器上的其他进程能读到你的路径信息。
- **不防御已取得你账户权限的本地攻击者**：对方能改日志也能直接改文件。
- **不提供跨机器一致性**：撤销日志是本机的，换机器无法回滚。
- **不保证杀软不误报**：PyInstaller 产物可能触发启发式告警；我们选择 onedir 以减少误报，
  但无法消除。请不要为此关闭实时防护。

## 支持的版本

阶段 0 尚未发布。发布后，只有**最新 minor 版本**接受安全修复；
更早的版本会在 `SECURITY` 里明确标注"不再维护"。

## 我们的承诺

- 安全修复会同时附带**回归测试**，测试必须能在修复前失败。
- 安全问题的修复不会"顺手"混进功能改动里。
- 如果某次安全修复需要破坏性变更，我们会在 Release Notes 里单独列一节说明影响与迁移方式。
